## 사용자 정보 반영 — 2026-10-20

- 개인 PC 개발·시연용 포트폴리오로 목표 확정. 기존 AWS 구조 재현은 필수 아님.
- 공개 저장소의 KOPIS 키가 HTTPS 조회로 유효함을 확인: SEC-01 키 폐기/교체가 가장 시급.
- 실제 사용자 유치 이력·보유 데이터 없음. LOCAL-02에 KOPIS 소규모 수집과 사람 검수 학습/평가셋 구축 추가.
- SEC-04 중 AWS 도메인/Netlify 운영 전환은 재배포를 선택할 때 진행. 로컬 키 보호·외부 HTTPS·인증서 검증은 유지.
- PERF-01은 먼저 로컬 환경에서 측정. AWS worker 증설을 전제로 하지 않음.
- 장비와 키 교체 상세 절차: `SECURITY_AND_LOCAL_AI_PLAN.md`.

## 우선순위 원칙

1. 노출 대응은 가장 먼저 시작한다. 실제 키 재발급 등 외부 작업을 기다리는 동안 독립적인 코드 수정은 진행할 수 있다.
2. 개인정보·데이터 정합성·학습 검수 신뢰성을 확보한 뒤 성능과 모델을 개선한다.
3. 테스트와 기록은 마지막 단계가 아니라 각 변경의 완료 조건이다.
4. 프론트 코드는 직접 수정하지 않는다. 꼭 필요한 요청은 FRONTEND_HANDOFF.md로 관리한다.
5. 심각도와 구현 순서는 다르다. 운영 정보가 필요한 HTTPS 작업을 기다리느라 로컬에서 가능한 결함 수정을 멈추지 않는다.
6. 운영 배포 완료와 로컬 검증 완료를 별도 상태로 기록한다.

## 사용자에게 필요한 정보와 조치

### 지금 또는 보안 대응 시작 시

- **서비스 현재 상태:** AWS 서버가 살아 있는지, 실제 사용자에게 공개되어 있는지, 보존해야 할 운영 데이터가 있는지.
- **KOPIS 키:** 로그의 값이 실제 사용했던 키인지, 아직 활성인지, 교체 가능한 계정에 접근할 수 있는지.
  실제 키이면 재발급·운영 환경변수 교체가 필요하다. 키 문자열을 채팅에 보내지 않는다.
- **저장소 공유 상태:** 공개/비공개 여부, 다른 사람이 clone했는지. 과거 이력 정리가 필요한 범위를 판단할 자료다.

### 운영 적용 전에

- Elastic Beanstalk 플랫폼, 인스턴스 CPU/메모리, 단일 인스턴스/로드밸런서 여부.
- API 도메인 및 인증서 보유 여부, Netlify→AWS 프록시 경로, Redis/Valkey TLS 설정.
- 환경변수는 이름과 설정 여부/비밀이 아닌 옵션만 공유. `.env` 전체, AWS access key, DB 비밀번호는 공유하지 않는다.
- 실제 DB 수정/이미지 삭제가 필요할 때 백업 상태와 삭제·보관 정책 확인.
- CI를 실행할 저장소·브랜치와 실행 권한, 작업을 전달할 프론트 담당자의 협업 가능 여부.
- 기존 인수인계서의 계정 복구 화면 등 과거 요청 완료 여부도 배포 점검 때 재확인한다.
  이번 15개 발견 사항과 별개이며 과거 체크박스만으로 현재 미구현을 단정하지 않는다.

### 로컬 AI 실험 전에

- 노트북/데스크톱 중 사용할 장비의 GPU 모델·VRAM·RAM·여유 저장 공간.
- '로컬 AI'가 개인 PC 개발/시연용인지, AWS 웹 서버가 호출할 상시 추론 서비스인지.
- 월 운영/학습 비용 상한과 원하는 응답 시간. 아직 모르면 기본 모델 실측 후 함께 결정.
- 현재 공연 데이터와 추천 세션/피드백 데이터의 존재 여부, 대략적인 규모, 학습 사용 권한.
  처음부터 원본 DB 전체를 받을 필요는 없다. 집계와 비식별 샘플부터 확인한다.
- 별도 학습 코드·노트북·모델 파일·데이터셋 저장소가 있다면 위치/자료. 없으면 현재 코드부터 시작할 수 있다.

## 추가 자료 없이 진행 가능한 범위

새 소스코드나 AWS 비밀키 없이도 SEC-01의 로그 처리, SEC-02, DATA-01/02, AI-01,
TRAIN-01의 보호 로직, SEC-03 로컬 제한 구현, PERF-02 및 회귀 테스트 준비를 진행할 수 있다.
운영 정보가 없다는 이유로 이 작업 전체를 보류할 필요는 없다.
